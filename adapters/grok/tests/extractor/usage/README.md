# Grok usage extractor fixture

`synthetic-grok-session-716/updates.jsonl` and `synthetic-grok-fork-716/updates.jsonl` are fully invented synthetic data shaped like the native XAI ACP update envelope. They cover response-level usage, duplicate message IDs, a turn-level aggregate that must be ignored, a fork copy with a new session ID and preserved `_meta.eventId`, and an unrelated update. The parent response without either identity field also covers the ordinal fallback. The neighboring `chat_history.jsonl` is a decoy: usage discovery must select only `updates.jsonl`.

The implementation follows the official [XAI session update type](https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-shell/src/extensions/notification.rs), [per-response projection and send path](https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-shell/src/session/acp_session_impl/updates.rs), and [response usage type](https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-sampling-types/src/conversation.rs). `ResponseCompleted` is one model response, including each response in a tool loop. It carries its provider `message_id` when supplied and `ResponseUsage` with uncached `input_tokens`, `output_tokens`, `cache_read_input_tokens`, `cache_creation_input_tokens`, and `reasoning_tokens`. The generic cache creation count maps to `cache_write_5m` because the source does not split its retention period. Reasoning is capped at output.

The turn handler emits each response update through the buffered XAI session-update pipeline. The session storage layer persists the notification in `updates.jsonl` inside an envelope with a Unix-seconds write timestamp. Session identity comes from the notification's `sessionId`. `ResponseCompleted` has no model field, so the extractor uses `__none`; it does not infer the model from session state. Dedupe prefers the provider message ID, then the persisted `_meta.eventId` (preserved across fork copies by the [native JSONL copy path](https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-shell/src/session/storage/jsonl/copy.rs); generated by [event_id.rs](https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-shell-base/src/util/event_id.rs)), then `<session_id>:<usage-record ordinal>` for older records without either identity. After the first per-response fact in a transcript, whole-turn totals are ignored to avoid counting the same work twice, including delayed totals for interleaved prompts.

Before the first per-response fact, `turn_completed` is the historical billable source. Its `modelUsage` entries preserve the actual model, inclusive input is split into uncached input/cache reads/cache writes, and reasoning is a subset of output. The installed Grok binary on 23 November 2026 documents `costUsdTicks` as 10 billion ticks per USD. Partial costs remain unpriced; no model is substituted. This is one aggregate usage record per turn and model, not an invented model-call count.

Output version 2 adds only those historical aggregate keys. The semantic gate proves every version-1 request remains identical, so the app can safely replay the files once without deleting or re-keying prior records. All other adapters keep the version-1 ceiling until their reconciliation semantics are implemented.

The persisted cursor includes the response ordinal and whether the transcript has entered the per-response format. It never grows with closed turns. A legacy byte cursor restores context once; subsequent appends seek directly to the saved offset. The 10×/100× scale test adds cold sessions and history but calls the parser once for one new turn. Tests also cover every resume boundary, native cost conversion, duplicate totals, mixed formats, empty turns and unchanged compressed archives.
