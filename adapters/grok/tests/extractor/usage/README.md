# Grok usage extractor fixture

`synthetic-grok-session-716/updates.jsonl` and `synthetic-grok-fork-716/updates.jsonl` are fully invented synthetic data shaped like the native XAI ACP update envelope. They cover response-level usage, duplicate message IDs, a turn-level aggregate that must be ignored, a fork copy with a new session ID and preserved `_meta.eventId`, and an unrelated update. The parent response without either identity field also covers the ordinal fallback. The neighboring `chat_history.jsonl` is a decoy: usage discovery must select only `updates.jsonl`.

The implementation follows the official [XAI session update type](https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-shell/src/extensions/notification.rs), [per-response projection and send path](https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-shell/src/session/acp_session_impl/updates.rs), and [response usage type](https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-sampling-types/src/conversation.rs). `ResponseCompleted` is one model response, including each response in a tool loop. It carries its provider `message_id` when supplied and `ResponseUsage` with uncached `input_tokens`, `output_tokens`, `cache_read_input_tokens`, `cache_creation_input_tokens`, and `reasoning_tokens`. The generic cache creation count maps to `cache_write_5m` because the source does not split its retention period. Reasoning is capped at output.

The turn handler emits each response update through the buffered XAI session-update pipeline. The session storage layer persists the notification in `updates.jsonl` inside an envelope with a Unix-seconds write timestamp. Session identity comes from the notification's `sessionId`. `ResponseCompleted` has no model field, so the extractor uses `__none`; it does not infer the model from session state. Dedupe prefers the provider message ID, then the persisted `_meta.eventId` (preserved across fork copies by the [native JSONL copy path](https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-shell/src/session/storage/jsonl/copy.rs); generated by [event_id.rs](https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-shell-base/src/util/event_id.rs)), then `<session_id>:<usage-record ordinal>` for older records without either identity. Whole-turn `TurnUsage` / `turn_completed` aggregates are ignored.

The invented legacy, mixed, modern, empty-turn, call-only, and cost-only fixtures distinguish old turn aggregates from per-response facts. A file with an aggregate whose turn has positive model-call, token, or known cost counters but no per-response usage finishes successfully and emits checkpoint `unrecorded: {reason: "legacy-turn-totals", count: 1}`. The count is affected history files, not guessed requests or turns. Aggregates paired with response rows, empty aggregates, and all-zero canceled turns do not trigger it. Context replay retains the diagnostic over every plain-text resume boundary. An unchanged compressed history skips both parser construction and decompression, emitting no optional diagnostic; the helper retains the previous diagnostic on that no-op. Aggregate counters are never converted into request events.
