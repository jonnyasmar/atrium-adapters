# Grok usage extractor fixture

`synthetic-grok-session-716/updates.jsonl` is fully invented synthetic data shaped like the native XAI ACP update envelope. It covers response-level usage, duplicate message IDs, a turn-level aggregate that must be ignored, an ordinal fallback when the message ID is absent, and an unrelated update. The neighboring `chat_history.jsonl` is a decoy: usage discovery must select only `updates.jsonl`.

The implementation follows the official [XAI session update type](https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-shell/src/extensions/notification.rs) and [per-response projection and send path](https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-shell/src/session/acp_session_impl/updates.rs). `ResponseCompleted` is one model response, including each response in a tool loop. It carries its provider `message_id` when supplied and `ResponseUsage` with uncached `input_tokens`, `output_tokens`, `cache_read_input_tokens`, `cache_creation_input_tokens`, and `reasoning_tokens`. The generic cache creation count maps to `cache_write_5m` because the source does not split its retention period. Reasoning is capped at output.

The turn handler emits each response update through the buffered XAI session-update pipeline. The session storage layer persists the notification in `updates.jsonl` inside an envelope with a Unix-seconds write timestamp. Session identity comes from the notification's `sessionId`. `ResponseCompleted` has no model field, so the extractor uses `__none`; it does not infer the model from session state. Dedupe uses the provider message ID, or `<session_id>:<usage-record ordinal>` when absent. Whole-turn `TurnUsage` / `turn_completed` aggregates are ignored.
