# OpenCode usage fixture

These fixtures are invented SQLite databases built from `fixture.sql`, `fork_fixture.sql`, and `legacy_fixture.sql`; they contain no user or owner data. They cover one assistant response, completed and failed compaction requests, a running compaction to ignore, a user message, a timestamp tie, missing model metadata, missing usage, present fork ancestry, deleted-parent siblings, and a deleted intermediate with a surviving grandparent. `expected.jsonl` and `legacy_expected.jsonl` pin the canonical usage events.

The parser follows OpenCode's official [session message ID and schema](https://github.com/anomalyco/opencode/blob/dev/packages/schema/src/session-message.ts), [SQLite session and message tables](https://github.com/anomalyco/opencode/blob/dev/packages/core/src/session/sql.ts), [fork projection](https://github.com/anomalyco/opencode/blob/dev/packages/core/src/session/projector.ts), and [token normalization](https://github.com/anomalyco/opencode/blob/dev/packages/core/src/session/usage.ts). It reads `session_message` assistant rows with `tokens` and compaction rows only when status is `completed` or `failed` and request tokens are present. `tokens.input` is fresh input, cache read/write are disjoint, and `tokens.output` is visible output, so canonical output adds reasoning while retaining reasoning as a subset. `data.model.id` supplies model, or `__none` when absent. Stored `cost` can be catalog-estimated and has no per-request provenance, so canonical `cost_usd` remains null.

Every request's canonical key is `<origin_session_id>:<seq>`; sequence is unique within each session. For a present parent, the fork boundary resolves the inherited prefix and the parser walks same-sequence rows to the origin session, so original and copied requests fold together. OpenCode generates ordinary IDs from an underscore-free 26-character ascending alphabet and fork copies as `<event-derived-id>_<seq>`. If a parent session is gone, that exact suffix still identifies copied rows, so they use `<missing_parent_id>:<seq>`, retain the child `session_id`, and set `fork_of` to the missing parent. Sibling copies therefore fold together. If an intermediate ancestor was deleted, its own parent lineage is no longer available: a surviving grandparent's event may remain separate from the child copy. The event's `fork_of` marker lets the usage view disclose that possible double count, consistent with OpenCode's [documented deleted-parent accounting case](https://github.com/anomalyco/opencode/issues/48306).

Legacy v1 reads the official [`message` table](https://github.com/anomalyco/opencode/blob/v1.19.5/packages/core/src/session/sql.ts) and its [assistant usage fields](https://github.com/anomalyco/opencode/blob/v1.19.5/packages/schema/src/v1/session.ts). Only completed assistant rows with nonzero usage count; partial streams and shell-only zero-usage messages do not. The [processor](https://github.com/anomalyco/opencode/blob/v1.19.5/packages/opencode/src/session/processor.ts) persists final counters before completion. The [prompt runner](https://github.com/anomalyco/opencode/blob/v1.19.5/packages/opencode/src/session/prompt.ts) records `time.created` with `Date.now()`, giving integer milliseconds; fractional timestamps are rejected.

V1 [forks](https://github.com/anomalyco/opencode/blob/v1.19.5/packages/opencode/src/session/session.ts) preserve usage and original time while regenerating IDs and omit origin metadata. Their content key is `opencode1:<created ms>:<native modelID>:<input>:<output including reasoning>:<cache read>:<cache write>:<reasoning>`. Rust canonicalizes the reported model separately. Copies collapse; attribution follows the normal earlier-time/smaller-session tie rule, with no `fork_of`. Two distinct calls with identical millisecond, model, and complete token vector can collide; the coverage note discloses content matching for pre-v2 history. Invented fixtures pin copied-parent removal, parallel calls with different vectors, and final streaming updates. A verified v2 ledger takes precedence when both schemas exist, avoiding duplicate migration history.

The official [database path](https://github.com/anomalyco/opencode/blob/dev/packages/cli/src/database-path.ts) uses `OPENCODE_DB` when set, relative to the OpenCode data directory unless absolute, otherwise `opencode.db` or channel-specific `opencode-*.db`. SQLite reads use the shared runner's read-only connection and snapshot transaction. Resume cursors are inclusive update timestamps, so equal-time rows replay safely and stable keys deduplicate them. Unknown or incomplete schemas remain unsupported without advancing the checkpoint.
