# OpenCode usage fixture

This fixture is an invented SQLite database built from `fixture.sql`; it contains no user or owner data. It covers one assistant response, completed and failed compaction requests, a running compaction to ignore, a user message, a timestamp tie, missing model metadata, and missing usage. `expected.jsonl` pins the canonical usage events.

The parser follows OpenCode's official [session message schema](https://github.com/anomalyco/opencode/blob/dev/packages/schema/src/session-message.ts), [SQLite session-message table](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/session.sql.ts), and [token normalization](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/usage.ts). It reads `session_message` assistant rows with `tokens` and compaction rows only when status is `completed` or `failed` and request tokens are present. `tokens.input` is fresh input, cache read/write are disjoint, and `tokens.output` is visible output, so canonical output adds reasoning while retaining reasoning as a subset. Dedupe is the persisted message ID; the session ID is the table's `session_id`. `data.model.id` supplies model, or `__none` when absent. Stored `cost` can be catalog-estimated and has no per-request provenance, so canonical `cost_usd` remains null.

The official [database path](https://github.com/anomalyco/opencode/blob/dev/packages/cli/src/database-path.ts) uses `OPENCODE_DB` when set, relative to the OpenCode data directory unless absolute, otherwise `opencode.db` or channel-specific `opencode-*.db`. The extractor supports the verified v2 `session_message` table; the older v1 message schema has not been verified for per-request usage and remains unsupported. SQLite reads use the shared runner's read-only connection and snapshot transaction. Resume cursors are inclusive timestamps, so equal-time rows replay safely and stable message IDs deduplicate them.
