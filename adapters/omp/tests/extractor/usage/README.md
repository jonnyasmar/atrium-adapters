# Synthetic OMP usage fixtures

Every record, model name, timestamp and token count is invented. The dedupe key is the native `<entry.id>` plus its normalized UTC millisecond entry timestamp; a short ID reused at another time remains a separate request. Entries without an id fall back to `<session_id>:<usage-record ordinal>`. The synthetic forks copy an inherited request into two sibling sessions, add new fork-local requests, and include a separate session that reuses the short ID at a different timestamp with a non-UTC offset. Inherited rows use the native `parentSession` reference as `fork_of` when their entry timestamp precedes the fork header timestamp; the origin-deleted batch is also checked. The session header id takes precedence over the supplied id, and resume tests cover every line boundary. OMP v16.5 stores normalized `Usage` fields: input excludes cache-read and cache-write tokens, output includes thinking and tool-call arguments, and reasoning is an optional subset of output. Its v16.5 format has no cache TTL split, so aggregate cache writes map to 5m. Missing model IDs become `__none`; catalog-estimated `usage.cost` remains `cost_usd: null`.

Official format and semantics: [OMP v16.5 session format](https://github.com/can1357/oh-my-pi/blob/v16.5.0/docs/session.md#message), [OMP v16.5 Usage type](https://github.com/can1357/oh-my-pi/blob/v16.5.0/packages/catalog/src/types.ts#L89-L143).
