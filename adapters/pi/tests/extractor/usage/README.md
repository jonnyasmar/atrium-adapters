# Synthetic Pi usage fixtures

Every record and token count here is invented. `message` entries use the documented Pi JSONL shape. The dedupe key is `<session_id>:<entry.id>`; when an entry has no id it falls back to `<session_id>:<usage-record ordinal>`. Repeated `pi-request-1` rows pin per-field-max folding, the metadata winner, and stable ordinal counting across resume boundaries. The session header id takes precedence over the supplied id. The compaction row deliberately carries invented usage but is ignored: only verified assistant-message usage is extracted. Cache reads and writes are already disjoint from input in Pi's normalized `Usage`; a provided `cacheWrite1h` is a subset of `cacheWrite`, and the remainder maps to 5m. Reasoning is a subset of output. Estimated `usage.cost` is not emitted as `cost_usd`.

Official format and semantics: [Pi session format](https://github.com/pi-packages/earendil-works-pi/blob/main/packages/coding-agent/docs/session-format.md#message-types), [Pi Usage type](https://github.com/earendil-works/pi/blob/main/packages/ai/src/types.ts#L442-L470), and [Pi OpenAI Responses normalization](https://github.com/earendil-works/pi/blob/main/packages/ai/src/api/openai-responses-shared.ts#L603-L620).
