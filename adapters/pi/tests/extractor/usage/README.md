# Synthetic Pi usage fixtures

Every record, model name, timestamp and token count is invented. The dedupe key is the native `<entry.id>` plus its normalized UTC millisecond entry timestamp; a short ID reused at another time remains a separate request. Entries without an id fall back to `<session_id>:<usage-record ordinal>`. The synthetic forks copy an inherited request into two sibling sessions, add new fork-local requests, and include a separate session that reuses the short ID at a different timestamp with a non-UTC offset. Inherited rows use the native `parentSession` reference as `fork_of` when their entry timestamp precedes the fork header timestamp; the origin-deleted batch is also checked. The session header id takes precedence over the supplied id, and resume tests cover every line boundary. The compaction row deliberately carries invented usage but is ignored: only verified assistant-message usage is extracted. Cache reads and writes are already disjoint from input in Pi normalized `Usage`; `cacheWrite1h` is a subset of `cacheWrite`, and the remainder maps to 5m. Reasoning is a subset of output. Estimated `usage.cost` is not emitted as `cost_usd`.

Official format and semantics: [Pi session format](https://github.com/pi-packages/earendil-works-pi/blob/main/packages/coding-agent/docs/session-format.md#message-types), [Pi Usage type](https://github.com/earendil-works/pi/blob/main/packages/ai/src/types.ts#L442-L470), and [Pi OpenAI Responses normalization](https://github.com/earendil-works/pi/blob/main/packages/ai/src/api/openai-responses-shared.ts#L603-L620).
